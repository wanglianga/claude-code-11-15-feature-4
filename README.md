# 生鲜订货决策系统

面向叶菜/根茎等短保生鲜的门店订货系统。四个各自持有状态的模块靠**不可变版本**串联：

```
需求还原 → 分位预测 → 门店改量 → 收市复盘
   ↑__________（复盘决定哪些样本允许回流）__________|
```

在此之上增加**新店新品试销**：没有销售历史时用「参照商品 + 少量实售」合算估计首批量，
每日按售出情况决定加订 / 继续观察 / 停止试销，满足连续有效营业日的覆盖与损耗检查后转入正式预测。

- **需求还原**：按门店/品类/到货日，把缺货时段、断货标记、售罄时点、有货时段销售速率整成**截断观测样本**；
- **分位预测**：基于还原样本生成带**特征快照**的建议版本（临界分位 × 特征因子，向上取整到最小订货单位）；
- **门店改量**：店长只在该版本上改量、记原因码并确认订单；
- **收市复盘**：按订单版本归因实销、报损、缺货损失，决定哪些样本回流需求还原。

任一模块重算都不改写下游已确认的记录。

## 写死的取舍（口径中途不能换）

| 取舍 | 规则 | 代价/后果 |
| --- | --- | --- |
| 训练目标 | **不直接拿实销当需求**。缺货日实销被货架截断，先还原成截断观测（有货时段速率 × 全天营业时长）再建模 | 门店必须回传断货标记；标记缺失时页面只能**降级为保守估计**（实销为需求下界，不外推） |
| 复盘基准 | 复盘以**观测需求**（还原后需求）而非实销为归因基准，与训练口径一致 | 口径选定后中途不能换 |
| 建议量 | 临界分位 **τ = Cu/(Cu+Co)**（Cu=缺货单位损失含客流损失，Co=报损单位成本）。叶菜默认 8/2→**高分位 0.8**，根茎 2/2→**中位 0.5**；同品类不同门店允许覆盖（cost_params） | 不用期望值给数：期望掩盖尾部风险；单价比标定错会让历史订单损耗归因整体偏移，故 Cu/Co 随版本快照固化 |
| 取整 | 建议量**向上取整到最小订货单位**的整数倍 | 规则写入版本快照 `rounding=ceil_to_min_order_unit` |
| 版本 | 建议版本**不可变**：促销取消/降温/配送延误触发重算只产生新修订版本；店长已确认的订单版本原样保留，复盘按当时版本归因 | 历史版本只读可查 |
| 并发 | 店长确认与总部修订同时落库 → **按落库先后裁定**，另一方收到 409 冲突提示；同一到货日重复提交按**幂等键**并成一张建议表 | 数据库行锁 + 幂等键唯一约束保证 |
| 账实不符 | 库存与盘点对不上**以盘点为准**并留差异记录；**差异批次从训练样本剔除** | 否则系统库存会把需求还原污染掉 |
| 报损补录 | 次日补录的报损单落在窗口内（营业日次日 12:00 前）才触发**结转重算**；过窗的单独存档并说明出处 | 当日已锁定的建议量保持原样 |
| 试销参照 | 参照商品按 **店型 / 商圈 / 规格 / 营业时段** 匹配，每个时段设定"参照数据相当于多少个有货小时"；参照销量与新品实售**合算**，同除有货时长得小时强度 | 只用实售反应快但首日一次团购会推高后续订货；合算后新数据随有效观察时长逐渐占优，代价是转变慢。页面同时展示**取消参照**的结果与少订/多订差额 |
| 试销缺失口径 | 售罄后的时段不按 0 销量计入，售罄时段只计"时段起点→售罄时点"的有效有货时长；**停业 / 漏报**不计入观察时长 | 漏报当日无法判断，故不计时长且转正检查判为不完整 |
| 试销决策 | 参照设定、每日观测、试销决策**分别保存**；参照失效只重估**未确认**计划，店长已确认的订货记录按当时快照冻结保留 | 停止试销与追加确认冲突时**拒绝旧计划**：未确认加订作废，已确认数量单列"待处理" |
| 试销观测 | 每日观测用**修订号**管理：后补有货时长时旧修订撤掉贡献（`is_current=false`）再计入新值；`import_key` 重复导入**不重复累加** | 同一营业日/时段只有一行当前修订参与估计 |
| 试销转正 | 按**连续有效营业日**检查泊松预测区间覆盖率与实际损耗；缺报或偏差持续过大继续观察；转正冻结当时参照、观测、决定与检查结果 | 门槛：连续有效 ≥5 日、覆盖率 ≥80%、损耗率 ≤15%、平均偏差 ≤35% |

## 技术栈

- 前端：React 18 + TypeScript + Vite + Zustand（三级筛选与建议表草稿状态）+ React Router
- 后端：Node.js 22 + Express + TypeScript + PostgreSQL 18（事务/行锁/唯一约束）
- 测试：Vitest + Supertest（后端 57 项）+ happy-dom 页面测试（前端 2 项）

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

- 前端：http://localhost:3000 （nginx，反向代理 `/api`）
- 后端：http://localhost:8080 （启动时自动建表；空库自动写入演示数据）

## 本地开发

前置：PostgreSQL 运行在 `127.0.0.1:5432`（库/用户/密码均为 `ccdev`，可用 `DATABASE_URL` 覆盖）。

```bash
# 后端（自动迁移 + 空库种子）
cd server && npm install && npm run dev        # http://localhost:8080

# 前端（/api 代理到 8080）
cd web && npm install && npm run dev           # http://localhost:5173

# 后端测试（独立测试库 ccdev_test / ccdev_trial，自动建/删）
cd server && npm test

# 前端页面测试（happy-dom）
cd web && npm test

# 类型检查 / 前端生产构建
cd server && npm run typecheck
cd web && npm run build
```

1. **建议与订货**（`hq` 登录）：选「降温超出预报」重算 → 生成 v2，v1 标记「已修订」且内容不变；
2. 同页（`store1` 登录）：在最新版本上改量、选原因码 → 确认订单；若总部先修订会收到冲突提示并自动刷新；
3. **收市复盘**：选前日到货日（2026-11-11）→ 查看按订单版本归因的实销/报损/缺货损失（基准：观测需求）；补录报损单（窗口内结转重算）、提交盘点（差异批次样本剔除）；

## API 概览

统一前缀 `/api`，除登录外均需 `Authorization: Bearer <token>`；冲突返回 `409 {error:{code,message,details}}`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/auth/login` | 登录 |
| GET | `/meta` | 门店/品类/SKU/成本参数/系统口径 |
| GET | `/samples` | 需求还原截断观测样本（门店+品类+日期区间） |
| GET | `/suggestions` | 建议表 + 版本列表 + 当前版本明细 + 已确认订单 |
| POST | `/suggestions/generate` | 生成/事件重算（总部）；幂等键并表；已确认则 409 |
| GET | `/suggestions/versions/:id` | 历史版本只读详情 |
| POST | `/versions/:id/confirm` | 门店确认（幂等键）；旧版本 409、重复确认幂等 |
| GET | `/orders` · POST `/orders/:id/review` | 订单查询 · 生成复盘（幂等） |
| GET | `/reviews` · POST `/reviews/:id/entry` | 复盘查询 · 录入当日实绩（还原+归因+样本回流） |
| GET/POST | `/waste-records` | 报损单（窗口内结转重算/过窗存档） |
| GET/POST | `/stocktakes` | 盘点（以盘点为准、差异批次剔除训练样本） |
| GET | `/trials/catalog` | 参照目录（按门店店型/商圈/规格列出各营业时段参照与等价有货小时） |
| GET/POST | `/trials` | 试销计划列表 / 创建（同店同 SKU 同到货日幂等） |
| GET | `/trials/:id` | 计划明细：参照集、观测（含历史修订）、估计版本、决策、确认、转正检查 |
| POST | `/trials/:id/references` | 保存参照设定（新修订版本） |
| POST | `/trials/:id/references/invalidate` | 判定参照失效：只重估未确认计划，已确认快照保留 |
| POST/DELETE | `/trials/:id/observations[/:obsId]` | 每日观测（修订号、importKey 幂等）/ 撤销当前观测 |
| POST | `/trials/:id/decisions` | 试销决策：`add` / `observe` / `stop`（停止会作废旧加订） |
| POST | `/trials/:id/confirmations` | 店长确认首批/追加（停止后确认旧决策 → 409 + 待处理列表） |
| GET/POST | `/trials/:id/graduation`·`/graduate` | 转正检查 / 转正（冻结参照、观测、决定与检查） |

## 目录结构

```
├── docker-compose.yml      # 一键启动：db + server + web(nginx)
├── server/                 # 后端
│   ├── src/lib/            #   需求还原、临界分位/取整/特征因子、日期、泊松分布、试销估计与转正检查
│   ├── src/services/       #   建议生成/确认（事务+幂等+冲突）、复盘/报损/盘点、试销计划/参照/观测/决策
│   ├── src/schema.sql      #   表结构（版本不可变、幂等键唯一、样本剔除标记）
│   ├── src/seed.ts         #   演示数据（确定性随机，可复现）
│   └── test/               #   Vitest：纯逻辑单测 + API 集成（独立测试库）+ 前后端复算一致性
└── web/                    # 前端
    ├── src/lib/            #   试销前端复算（与后端同口径的泊松分位与覆盖检查）
    ├── src/pages/          #   需求还原 / 建议与订货 / 新品试销 / 收市复盘
    └── test/               #   happy-dom 页面挂载测试（渲染 + 切店竞态）
```
